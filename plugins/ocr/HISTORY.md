# ocr 历史

> 只记这枚插件**对外可见**的变化：结果内容、manifest 的能力与设置项、随包文件。
> 标题版本 = `manifest.json` 的 `version`，日期 = `plugins.json` 的 `released`。
> **这里不写发布进度**（不写「待上传 / 未发布 / tag / ZIP 是否生成」）——那些的唯一真源是 `plugins.json`。

## 0.1.0 — 2026-11-11 — protocol 1

- **新增**：第一枚文字识别插件（命令型），命名「**OCR 文字识别**」。对当前打开的图片
  离线识别，输出纯文本，由宿主自动复制到剪贴板。识别引擎与模型全部随包，
  不联网、不上传图片、不写插件目录以外的地方。
- **一次识别同时覆盖中文（简体 / 繁体）、英文、数字与常见符号**：只有一套 rec 模型 +
  一份字典（6623 字，其中 6270 个 CJK 统一汉字、94 个 ASCII 可打印字符、10 个希腊字母、
  15 个数学符号、5 个箭头）。简繁在这套 Unicode 码位里是同一批字，字典不分语言，
  所以简繁英混排一张图一次全出，**不做「识别语言」开关**。
- **为什么不做语言开关（实测后收敛）**：初版曾带一套繁体专用 rec 模型 + 字典做成二选一，
  繁体图第二行能多认 `擊` / `螢`，但简体图会被翻成繁体（`正品促销`→`正品促銷`、
  `划算`→`切算`）；两套同时跑引擎又不给置信度，没有依据选哪份对。删掉繁体专用档后
  简繁英混排一次全出，随包引擎/模型文件从 7 个降到 **5** 个。
- **符号范围如实列出**：字典自带 10 个希腊字母、15 个数学符号、5 个箭头、94 个 ASCII
  可打印字符、全角与 CJK 标点等；CTC 字典在训练时定死，不能靠改字典扩充字符。
  「字典里有」≠「一定认得出」：符号行 `α β ∑ √ → ± ℃ ①` 实测输出 `αβM<→`。
- **不支持**：日文、韩文、俄语等西里尔文字、带重音的拉丁语系；边界写进随包 README。
- **设置**：只有 `hotkey`，出厂空，不抢用户的键。
- **能力**：`image.read`、`clipboard.write`、`settings.read`、`settings.write`、
  `process.spawn`、`file.write`。**不声明** `image.sampled`：抽样会跳掉笔画。
- **失败形状**：包里五个文件缺任何一个、引擎起不来 / 非零退出 / 超过 25 秒 /
  输出里没有 `textLine` 行、以及整图超过 8 MP 拿不到像素，都明确报中文原因，不假装识别成功。
- **随包文件**：`ocr.exe`、`manifest.json`、`README.md`、`LICENSE`（MIT）、
  `engine/` 下 5 个文件（引擎 + det / cls / rec + 字典）、`ENGINE-NOTICE.md`
  （生成器会覆盖 `THIRD-PARTY-NOTICES.md`，所以外部引擎的许可另放一份随包），
  以及构建时生成的 `LICENSE-NOTICE.md` 与逐包许可表。
- **清理**：引擎 CLI 写死了输出画框结果图（无开关），会在输入图旁边落
  `<name>-result.jpg` / `.txt`；插件的退出守卫把这两份和临时 PNG 一起删掉，
  资产脚本在打包前还会清掉 `engine/` 里不在哈希清单上的残留文件。
- **依赖**：`serde_json` + `windows`（只开 `Win32_Foundation` / `Win32_System_Memory`）；
  PNG 编码、CRC-32 / Adler-32 / stored deflate 都在插件内实现，没有新增第三方 crate。
- **验证**：12 条单测（含「只带一套 rec、manifest 里没有语言下拉」的负向判据）、
  帧往返、未知 action、缺像素、假共享内存、`textLine` 乱序与括号、白底合成与 PNG chunk CRC；
  引擎与模型的 SHA256 由 `fetch_assets.py` 在每次构建前逐个核对。
