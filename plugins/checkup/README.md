# checkup（图片体检）

对**当前打开的图片**一次算完六段读数，输出一段可复制的 Markdown。它是"图进、报告出"的
`command` 型插件：不开窗口、不解码文件、不联网、不写任何地方。

```
## 基本信息    尺寸 / 像素量 / 朝向 / 最简比例（并对常见画幅点名）
## 透明度      不透明 / 半透明 / 全透明 三档计数 + 唯一色（带封顶）
## 颜色        平均色与平均不透明度（只在看得见的像素上求）
## 主色板      Median Cut 取代表色，按占比降序
## 对比度      四角中位色投票定背景 + 最多数的非背景色当前景 → WCAG 2.1 判级
## 清晰度      灰度 4 邻域拉普拉斯方差
```

## 数据从哪来

宿主在请求里给一块共享内存整图（协议 v1 §3 的 `image`、§5 的布局），插件只读打开。
★ 拿到的是**屏上朝向**那一份：宽高可能随旋转/镜像与原图对调，所以「基本信息」段的尺寸行
带着 `（横）/（竖）/（方）` 一起印出来。
只有本插件声明了 `image.read`、且当前整图不超过宿主的编辑档上限（8 MP）时宿主才下发像素；
不满足时本插件**如实报错退出**，不猜。

## 三条读数纪律

1. **公式写死并注明出处**（每条都写在代码行旁）：
   - 比例 = 宽高同除最大公约数；只在误差 < 2% 时才点名 1:1 / 4:3 / 3:2 / 16:9 / 16:10 / 9:16 / 21:9；
   - 主色板 = Median Cut（H. Heckbert, *Color Image Quantization for Frame Buffer Display*, SIGGRAPH 1982），
     **确定性**：不引 K-Means（要随机初值 ⇒ 同一张图两次跑出两份色板）；
   - 对比度 = WCAG 2.1 相对亮度与 `(L亮+0.05)/(L暗+0.05)`，4.5 = AA、7.0 = AAA、3.0 = 仅大号字；
   - 清晰度 = Rec.601 luma 上的 4 邻域拉普拉斯响应方差。
2. **每段都印"实际看了多少点、步长多少"**：一张 8 MP 的图只看了 20 万个点也能算出两位小数，
   "数字看着精确、其实只看了百分之一"是最容易骗人的读数。
3. **平票规则写死**（四角背景投票平票取左上、前景平票按色值升序）：判词不许依赖遍历次序，
   否则同一张图两次能给出两个答案。

## 设置（齿轮 → 宿主渲染的设置窗）

manifest 用**声明式设置**（协议 v1 的 `settings`）交代两格，宿主按清单画窗口、值存
`plugins/checkup/settings.json`，每次调用随请求下发：

| 键 | 界面 | 取值 |
|---|---|---|
| `palette` | 「主色板色数」下拉 | `4` / `8` / `16`，默认 `8` |
| `hotkey` | 「快捷键」捕获框 | 出厂**空**；绑了就能不右键直接跑本插件 |

优先级：**设置里的 `palette` > 命令行 `--colors`**（后者是 `manifest.args` 里的兜底值，
给"没有设置区"的老形态用）。两处都不合法时不就近取档——报告里直接声明
"`--colors` 只认 4 / 8 / 16，本次按默认 8 色算"，而不是悄悄换成别的数。

## 清晰度那一档为什么不能横着比

拉普拉斯方差的**绝对值随分辨率与缩放档漂移**（同一张图缩到一半，边缘响应会掉一大档），
所以它只在同批图之间比谁更糊。报告里把这句话印在数字旁边，不留在文档里。

## 构建

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
```

产物写到工作区 `.temp/plugin-dist/checkup/`（`checkup.exe` + `manifest.json`）。

## 冒烟（不用开 GUI）

```powershell
cd <宿主>\main
set RUPIX_DECODERS_DIR=<工作区>\.build\decoders
cargo run --release --example plugin_smoke -- ..\.temp\plugin-dist\checkup <一张真实图片>
```

探针走两腿：先送一张 4×2 的探针图（验"通道通、字节不错位"），再用宿主自己的解码栈
真解一次那张图片、把真实像素送进来，把整份报告打到 stdout。
