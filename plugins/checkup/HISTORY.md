> 协议与字段本身的史在 `protocol/protocol-v1.md` 与 `插件开发规范.md`（都在仓库根方向）；这里不重复。
> 标题版本 = `manifest.json` 的 `version`，日期 = `plugins.json` 的 `released`。

## 0.1.0 — 2026-10-31 — protocol 1

- **新增**：第一枚官方分析型插件。对**当前打开的图片**一次算完六段读数，输出一段可复制的
  Markdown——「基本信息」（尺寸 / 像素量 / 朝向 / 最简比例，误差 < 2% 才点名 16:9 这类画幅）、
  「透明度」（不透明 / 半透明 / 全透明三档计数 + 唯一色，带封顶）、「颜色」（平均色与平均不透明度，
  只在看得见的像素上求）、「主色板」（Median Cut 取代表色，按占比降序）、「对比度」（四角中位色
  投票定背景 + 最多数的非背景色当前景 → WCAG 2.1 判级，4.5 = AA、7.0 = AAA）、「清晰度」
  （Rec.601 灰度 4 邻域拉普拉斯方差）。
- **读数纪律**（这一格是这枚插件的立身之本，写进结果而不是只写进文档）：每条公式都注明出处；
  **每段都印"实际看了多少点、步长多少"**——一张 8 MP 的图只看了 20 万个点也能算出两位小数，
  "数字看着精确、其实只看了百分之一"是最容易骗人的读数；平票规则写死（背景平票取左上、
  前景平票按色值升序），判词不依赖遍历次序。
- **影响**：右键「插件」→「图片体检」即出报告；命令型插件从此能拿到宿主解好的整图像素
  （屏上朝向那一份），`image.read` 这个能力位对命令型也算真话了。
- **能力**：`image.read`、`settings.read`、`settings.write`。
- **设置**（宿主按 manifest 渲染的设置窗，值存 `plugins/checkup/settings.json`）：
  「主色板色数」下拉 `4` / `8` / `16`，默认 `8`；「快捷键」出厂**空**（不绑键，避免抢用户的键）。
  设置里的色数**优先于** `manifest.args` 的 `--colors`（后者只是没有设置区时的兜底）；
  两处都不合法时不就近取档，报告里直接写明按默认 8 色算。
- **失败形状**：拿不到整图（切片态 / 超过宿主编辑档上限 8 MP）时**如实报错退出**，不猜、
  也不假装"这张图没有问题"。
- **随包文件**：`checkup.exe`、`manifest.json`、`README.md`、`LICENSE`（MIT），
  以及构建时生成的 `LICENSE-NOTICE.md`（许可与源码位置）与 `THIRD-PARTY-NOTICES.md`
  （这枚插件的逐包许可表：静态链接的 crate 共 23 个包）。
- **依赖**：`serde_json` + `windows`（只开 `Win32_Foundation` / `Win32_System_Memory` 两个 feature，
  共享内存与句柄用）；不联网、不解码文件、不写任何地方。
- **验证**：单测 29 条，全在 `build.ps1` 里跑；纯函数优先、像素自己造夹具，可无头跑。
