# levels（色阶分析）

把**当前打开的图片**的明暗家底摊开：全量统计 R / G / B / 亮度四组 256 箱，
输出一段可复制的 Markdown 读数，并自己画一张 640×360 的四线叠加分布曲线图。
它是 `command` 型插件：不开窗口、不解码文件、不联网、不写任何地方。

```
## 色阶分析
- 统计范围：640×480 共 307200 像素；实际统计 307200 点（全量，未抽稀），跳过全透明 0 点。
- 亮度（Rec.601 整数近似 (77R+150G+29B)>>8）：均值 118.4 / 中位数箱 116 / 峰值箱 104（4210 点）。
- 暗部溢出（亮度 0–5）：12 点（0.00%）；高光溢出（亮度 250–255）：301 点（0.10%）。
- 三通道均值：R 132.1 / G 118.0 / B 104.6 → 通道差 Δ=27.5 > 12，R 通道整体偏高，画面偏红色。
- 纵轴：四格共用同一纵轴，满格 = 四组里最大的那一箱（4210 点，占实际统计 307200 点的 1.37%）；图上五条刻度（基线 0.00% 起）标的是占全图的百分比，理论上限 100%（所有可见像素落在同一箱）。
- 图形：已生成 640×360 PNG（四条平滑曲线叠加，只描线不上面积色），由宿主开新看图窗口显示……
```

## 图怎么读

横轴是亮度 0（纯黑）到 255（纯白），曲线的高度 = 有多少像素落在这一档
（纵轴刻度按占全图的百分比标，见下）。

- **堆在左边** → 欠曝，暗部糊成死黑；
- **山形居中、两头都不贴边** → 明暗都有内容；
- **堆死在右边** → 过曝，高光变纯白，那部分细节已经丢了。

图是**四条平滑曲线叠在同一绘图区**（逐列 Catmull-Rom 样条，手写零依赖）：红=R、
绿=G、蓝=B、白=亮度，共用同一纵轴。**只描线、不给曲线下面积上色**——面积色才是
"叠在一起看不清"的元凶，纯细线交叉处只有一两像素，谁是谁一眼可辨。绘图区
**四边有闭合框线**（底线就是 0% 基线）。刻度：横轴 **0 / 64 / 128 / 192 / 255**
五档；纵轴右侧五条刻度 = 基线 **0.00%** + 峰值的 25/50/75/100%，标的是**这一档
像素占全图可见像素的百分比**，分母 = 实际统计点数（跳过 alpha=0），与文本报告里的
溢出比例同一份。曲线仍按四组峰值箱归一化铺满，所以**顶线 = 本图峰值箱占比**（上面
那份样例是 1.37%），不是固定 100%；100% 只是理论上限（所有可见像素落进同一箱）。
换一张图、换一个画幅，刻度仍是同一个量纲，能横着比。精确读数看文本报告。

★ 图形怎么打开：PNG 由宿主落到 `<exe>/temp/` 后，宿主**自己开一个新的看图窗口**显示，
不是在当前窗内嵌；结果窗里的 `text` 是数字报告。不交系统关联——2026-11-04 之前交给
系统时，本机把 `.png` 关联到 RuPix 自己、又没开多开，插件产物会把用户正在看的图顶掉。

## 数据从哪来

宿主在请求里给一块共享内存整图（协议 v1 §3 的 `image`、§5 的布局），插件只读打开。
拿到的是**屏上朝向**那一份（旋转/镜像后的宽高）。只有声明了 `image.read`、且当前整图
不超过宿主编辑档上限（8 MP）时宿主才下发像素；拿不到时**如实报错退出**，不猜、不画空图。

统计三条纪律：

1. **不抽稀**：8 MP 以内全量遍历，报告里印"实际统计 N 点（全量，未抽稀）"。
2. **跳过 alpha=0**：屏幕上那些位置是棋盘格，不是图像颜色；报告里印跳过多少点。
3. **公式写死**：亮度 = `(77R + 150G + 29B) >> 8`（Rec.601 整数近似），与 `checkup`
   的清晰度段同一份灰度定义；峰值箱平票取箱号小的那个，判词不依赖遍历次序。

## 画图不需要额外工具

这枚插件的依赖只有 `serde_json` + `windows`（与 `checkup` 完全相同，**没有新增任何 crate**）：

| 步 | 做法 |
|---|---|
| 分箱 | 四组 × 256 个 `u32` 累加，纯整数运算 |
| 画曲线 | 逐列 Catmull-Rom 采样 + 两像素纯色描边，**不给曲线下面积上色**；不用绘制 API |
| 编 PNG | 手写 `zlib stored-deflate` 块 + Adler-32 + CRC-32 + 三个 chunk（IHDR / IDAT / IEND） |
| 回传 | 自己写 base64，塞进响应的 `open_image` |

stored deflate 是 zlib 的合法（不压缩）块类型，任何看图程序都认。代价只是 PNG 稍大
（640×360 ≈ 0.9 MB，base64 后 ≈ 1.2 MB，远低于协议的 16 MiB 单帧上限），
换来的是依赖树零增长——插件是独立进程，**宿主 exe 一个字节都不涨**。

## 设置（齿轮 → 宿主渲染的设置窗）

| 键 | 界面 | 取值 |
|---|---|---|
| `open_image` | 「同时生成分布曲线图」勾选 | 默认**开**；关掉只出文本，不弹外部看图程序 |
| `hotkey` | 「快捷键」捕获框 | 出厂**空**；绑了就能不右键直接跑本插件 |

注意：关掉 `open_image` **只影响有没有那张 PNG**，所有数字完全不变——有单测钉着这一点。

## 构建

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
```

产物写到工作区 `.temp/plugin-dist/levels/`（`levels.exe` + `manifest.json`）。

## 冒烟（不用开 GUI）

根目录的 `main/examples/plugin_smoke.rs` 可以真起一次插件进程（管道 + 共享内存 +
动态热键两腿）。另外在工作区 `.temp/m215/levels_probe.py` 有一份迷你宿主探针：
自己建命名管道与共享内存，发一张纯色夹具，把响应的 `text` 与 `open_image` 的 PNG
都解出来逐项核对（签名 / CRC / 通道峰值位置），全程不碰宿主源码。
