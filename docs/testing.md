# 测试与门禁（testing.md）

## 1. 门禁（根 `build.ps1` 强制，红了不出包）

| 门禁 | 查什么 | 自证 |
|---|---|---|
| `tools/check_manifests.py` | manifest 结构、字段类型、能力白名单、`id` = 目录名、`settings_ui` 需 `settings.write` | — |
| `tools/check_licenses.py` | **每个插件**解析出的全部依赖都有许可证且在 `ALLOWED` 里；**扫 0 个判失败**（"没东西可查"不等于"都合格"） | `--selftest`（8 条失败臂）；`--list` 印全集 |
| `tools/check_secrets.py` | 六条高置信判据：私钥块 / 令牌前缀（带够长的实体）/ URL 内嵌凭据 / 口令**字面量** / 邮箱（署名与许可证文件豁免）/ 含真名的 `C:\Users\<名字>`。**判据窄是刻意的**——天天误报的门禁最后会被加白名单加到失效 | `--selftest`（14 条：六条各自抓得到 + 四组不该报的不误报 + 豁免 + 失明 + 本仓现状） |
| `tools/check_docs.py` | **五查**：`docs/*.md` 与根文档的相对链接可达、`DOCS_MANIFEST.md` 登记齐、无本机绝对路径、根 `README.md` 的「发布插件」表与 `plugins.json` 按显示口径等值（大小 `x.xx MB` 由清单字节经 `fmt_size_mb` 换算，1 MB = 1024² B）、**每枚插件 `README.md` / `HISTORY.md` / `LICENSE` 齐备**（HISTORY 每条标题 `## <版本> — <日期> — protocol N`，首条的版本 / 日期 / protocol = manifest，条目不写发布进度） | `--selftest`（32 条） |

四条门禁都**自己发现**要查的对象（扫目录 / 扫文档 / 扫依赖图），不靠一张手维护的清单——
清单式门禁失明的地方正是"忘了加一行"。

## 2. 单测

每枚插件在 `build.ps1` 里先跑自己的测试：

```powershell
cargo test --release --manifest-path plugins/<id>/Cargo.toml --target-dir ../.temp/plugin-target/<id> -- --test-threads=1
```

- **`--test-threads=1` 是硬性**：多线程 runner 会被杀软锁二进制，表现为假死。
- 测试要能**无头**跑：纯函数优先；需要像素的（条码/体检）自己造夹具，不依赖外部样张。
- **夹具几何也是判据**：条码夹具两码之间必须留 ≥ 每侧 4 个模块的静区，
  否则多码读取器也只认一枚——那不是产品缺陷，是夹具不合格。

## 3. 冒烟（不用开 GUI）

```powershell
cd <宿主>\main
set RUPIX_DECODERS_DIR=<工作区>\.build\decoders
cargo run --release --example plugin_smoke -- ..\.temp\plugin-dist\<id> <一张真实图片>
```

探针两腿：先送一张 4×2 的**探针图**（验通道与字节不错位），再用宿主自己的解码栈
真解一次那张图、把真实像素送进来，把整份报告打到 stdout。

## 4. 真机验收（用户手动，写清预期）

| 步骤 | 预期 |
|---|---|
| 右键 →「插件」→ 某命令型插件 | 出结果窗，内容与冒烟一致 |
| 插件卡齿轮（声明了 `settings`） | 宿主渲染的设置窗：白底、按钮贴底、改动存得住；两列宽度与设置页一致 |
| 快捷键页 →「插件快捷键」 | 行名 `插件名 > 设置项名`；绑定后与插件设置窗一致 |
| 绑一把已被占用的键 | 原来占着的一方**自动变空**（同键抢占） |
| 勾上「解码后直接打开网址 / 图片」再跑 | 网址弹系统浏览器；图片弹**新看图窗口**（宿主自己开）；**不勾时什么都不打开**，结果窗照旧 |
| 设置 → 插件 →「可下载」→ 刷新 | 按所选下载源拉到远端清单；tag/资产没上传时如实报"下载失败"，不静默 |

## 5. 发布前必跑

`build.ps1`（含四条门禁）→ 各插件单测全绿 → 冒烟两腿 → 上面那张真机表逐行走一遍。
缺一项就写"未验"，不许拿"应该没问题"顶。
